# 移动 Web 验证记录

实现范围：原有 28 个页面（26 个业务页、登录、注册），患者/医生/管理员角色，15 个业务列表卡片适配。

## 执行结果

- `npm test`：3 项组件测试通过。验证字段完整性、零值、文本安全渲染、正确的行及索引传递、操作按钮及空状态。
- `npm run build`：通过，产物为 `client/dist`。依赖的 PURE 注释和大于 500kB 的构建包有警告，未阻止构建。
- Playwright 全量测试：14 项通过，耗时 36.2 秒。调整截图等待 CSS 动画完成后，另复跑三角色菜单测试，3 项通过。
- 测试浏览器：本机 Chromium；业务页面检查 320 / 390 / 430 / 1440px。AI 聊天补充 560px 短视口检查。
- 源码审查：三角色菜单入口及 15 个列表的字段/操作插槽未发现遗漏。已修正样式覆盖、聊天历史加载期间发送的竞态，并允许长症状标签换行。
- 本地前端 `http://127.0.0.1:5173` 返回 HTTP 200。局域网地址由 Vite 输出为 `http://192.168.1.11:5173`。
- 本地后端 `http://127.0.0.1:8000` 当前不可连接。

## 验证边界

浏览器测试拦截全部 `/api/v1` 请求，使用模拟数据，未操作真实患者或后台业务数据。已验证咨询/预约提交、医生回复/预约确认、管理员编辑/搜索/分页的请求内容，以及 AI 历史和流式回复显示。未完成真实数据库、Neo4j、AI 服务、文件存储的联调，也未进行 iOS Safari 或微信内置浏览器真机测试。

启动方式和功能清单见 `client/README.md`。
